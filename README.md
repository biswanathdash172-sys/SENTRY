# SENTRY — Demo Build

Human-Governed Autonomous SOC with integrated media/identity integrity
detection. This is the **hackathon demo scope**: real backend logic
(correlation engine, playbook engine, media integrity checks), in-memory
storage instead of Postgres, and a simple static HTML frontend instead of
the full React app described in `ARCHITECTURE.md`. See that file for the
full production file tree if/when the team wants to build it out further.

## Run the backend

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --reload --port 8000
```

Check it's alive: http://localhost:8000/health
Interactive API docs (auto-generated by FastAPI): http://localhost:8000/docs

## Run the frontend

No build step. Just open `frontend/index.html` directly in a browser
(or serve it with `python3 -m http.server` from the `frontend/` folder).
It talks to the backend at `http://localhost:8000` — edit the `API`
constant near the top of the `<script>` tag if you deploy the backend
elsewhere.

## What's real vs. demo-mode

| Piece | Status |
|---|---|
| Correlation engine (evidence → one explained alert) | Real logic, rule-based |
| Playbook engine (auto vs. manual, risk classification) | Real logic, rule-based |
| Human-in-the-loop approve/deny | Fully functional, updates audit log |
| Media signature check | Toy in-memory registry (see `SIGNED_REGISTRY`) |
| Deepfake scan | Deterministic heuristic, not a trained model — see docstring in `media_integrity_service.py` for the upgrade path and why this is intentional for a live demo (never crashes, always repeatable) |
| Database | In-memory dict, seeded on boot — see `models.py` docstring for the Postgres swap-in path |
| Live updates | 4-second polling from the frontend, not WebSocket |

## Flagship demo flow

1. Open the frontend — the "Likely deepfake-powered wire-fraud attempt"
   alert is already seeded and fully correlated (3 evidence sources, attack
   chain, playbook with auto + manual actions).
2. Click into it, walk through the Attack Chain → Media Verification Panel
   → Playbook → Provenance Log, left to right.
3. Click **Approve** or **Deny** on a manual (high-risk) action to show the
   human-in-the-loop gate live, and watch the Provenance Log update.
4. Click **"Simulate incoming alert"** in the header to show the full
   pipeline running live: new media evidence → correlation → a brand-new
   alert appearing in the stream within ~4 seconds.
