## Notes on sequencing

- Stages 1–4 (research, competitor analysis, scope, UI design) should be **mostly done before Stage 5–8 (architecture/backend/frontend) begins** — don't write code against an undefined scope.
- Stages 5–9 (architecture, DB, frontend, backend, AI) can run **in parallel** once scope is locked — this is the biggest time block, see `ROADMAP.md`.
- Stages 10–13 (review, security, performance, QA) happen continuously in the background, not as one final step — do a quick pass after each major feature lands, not all at once on the last day.
- Stage 16 (pitch deck) explicitly runs in parallel from day one — don't wait for the product to be finished to start telling its story.
